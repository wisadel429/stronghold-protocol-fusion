# 民间卫戍协议 · 独立版 UI 布局编辑器（图片替换版 1.1.0）

> 在 1.0.0 的基础上新增：**用图片替换游戏 UI** + **UI 构成分析**。

给《民间卫戍协议：盟约》调界面元素位置 / 大小的独立工具。**内置浏览器**（WebView2）直接打开，左侧是游戏画面预览，右侧是编辑侧边栏，选中元素即可实时拖动、缩放、改数值。

```
双击 Start.bat  →  选择游戏目录（内置目录页）  →  自动起服务端 / 代理  →  编辑台
```

## 1. 运行要求

- Windows 10 / 11（64 位）
- **WebView2 运行时按顺序自动查找**（不必随包分发）：
  1. 工具目录 `webview2\`（可选，放了就优先用这个固定版）；
  2. **所选 / 上次用过的 / 附近检测到的游戏目录里的 `webview2\`**（游戏包一般自带）；
  3. 系统安装的 Evergreen WebView2 运行时 —— **保证「选游戏目录」这个前置页面在还没选目录时也能先打开**。

  想把运行时一起带走：把游戏目录的 `webview2` 文件夹复制到工具目录即可。
- Node.js：优先使用**所选游戏自带的 `node\node.exe`**；没有的话依次找工具目录 `node\node.exe`、`PATH`、`C:\Program Files\nodejs\node.exe`。
- 端口：游戏服务端默认从 `3000` 开始（被占用会自动顺延到 3001、3002…）；编辑代理默认从 `3123` 开始顺延。

## 2. 启动与选择目录

1. 双击 **`Start.bat`**（或 `launch.ps1`）。
2. 打开内置的「选择游戏目录」页：磁盘、面包屑、目录列表、最近使用、校验项。
   - 选包含 `public\index.html` 和 `server\` 的那一层；
   - 页面**不会自动锁定目录**，必须自己点选后按「载入并打开编辑器」；
   - 工具目录附近如果已经有游戏，会在左侧「检测到附近的游戏目录」里提示，点一下即可选中；
   - 备份目录（名字带 `before-rollback` / `backup` / `old` / `.bak`）不会出现在推荐里。
3. 工具会校验目录、安装编辑器资源、启动服务端和代理，然后进入编辑台。

也可以把游戏文件夹直接拖到 `Start.bat` 上；仍然会在选择页确认，不会直接开。

## 3. 编辑台界面

- **左侧画面区**：占大部分宽度
  - 电脑版：**1920×1080（16:9）** 舞台，按窗口等比缩放（通常 80% 左右），按游戏设计分辨率渲染，文字清晰；
  - 手机端：**767×329（21:9）** 舞台，触发游戏的手机布局；该模式会通过 WebView2 把渲染 DPR 提到 2×，放大后不发糊。
  - 舞台左上角显示当前比例；右上角有「适应」按钮。
- **右侧侧边栏**（约 330px，不再有悬浮窗）：
  - 当前选择：层级面包屑、元素名、实际尺寸、父级/子级/同级/清空；
  - 位置与尺寸：X / Y / 宽 / 高 / 缩放% / 层级，输入即生效；
  - 微调方向键：长按连发，整段只记一个撤销点；
  - 已调整列表：点条目定位、↺ 删除单项；
  - 布局存档：按游戏版本自动对应，可多份存/读/删；
  - 底部：保存（Ctrl+S）、撤销/重做、重载、导出 CSS、清空。
- **高亮模式按钮**（预览区左上）：
  - 当前在 UI 编辑 → 显示 **「切换为游戏内点击」**（绿色）；
  - 当前在游戏内点击 → 显示 **「切换为UI编辑」**（琥珀色）；
  - 快捷键 `Tab`。UI 编辑模式下点击只选中、不触发游戏按钮；`Alt+点击` 可临时放行。
- **缩放手柄**：选中元素后，四角各一个小方块、四边各一个细长矩形，拖动即可自由放大/缩小；
  拖角保持比例（按 Shift 可开/关），拖边只改宽或高。手柄在屏幕上大小固定，不随舞台缩放变粗变细。
- **双击选父级**：双击一个元素会选中它的上一层（例如按钮里的文字 → 按钮；按钮 → 容器）。
- 元素列表 / 面包屑 / 父级按钮也可以切换层级；多选支持拖动整组移动、拖四角整组缩放。

## 3.5 图片替换 UI（1.1.0 新增）

**游戏 UI 是什么做的**（工具里的「构成分析」会直接告诉你）：

| 部分 | 实现 |
| --- | --- |
| 界面框架 / 按钮 / 标题 | Preact 渲染的 DOM + CSS（渐变、边框、`::before` / `::after` 装饰层） |
| 图标、徽记 | 内联 `<svg>` |
| 背景、立绘 | `<img>`（如 `/assets/.../ui/entry/bkg_01.png`） |
| 战场 | Canvas（图片替换对它无效） |

所以「图片替换」按元素逐个做，效果最好的是按钮、图标、标题这类 CSS 绘制的部件。

**用法**

1. 在左侧选中要换的元素；
2. 右侧「图片替换」→ **选择图片…**（PNG / JPG / WEBP / GIF，≤ 20MB）；
3. 选模式：
   - **替换原样式**：图片铺满元素，隐藏原文字 / 图标 / 伪元素装饰、去掉边框（推荐给按钮、图标）；
   - **覆盖在上层**：图片以 `::after` 盖在元素上，原样式和点击都保留（推荐给带复杂效果的部件）；
4. 选适配：铺满裁剪 / 完整显示 / 拉伸；
5. 点 **保存** 写入布局；`×` 清除该元素的图片。

**图片存在哪**：`<游戏目录>\public\ui-editor\images\skin-<哈希>.<ext>`，按内容哈希命名（同一张图不会重复存）。
布局 JSON 里只记 `/ui-editor/images/skin-xxx.png` 这个相对路径，普通开局（不经编辑器）也能显示。

**注意**：图片替换只在所选设备方案（电脑版 / 手机端）生效；换游戏版本后元素结构可能变，选择器失效时该项不会命中。

## 4. 对游戏目录做了什么

只有三处，都是可逆的：

| 位置 | 改动 |
| --- | --- |
| `public/ui-editor/` | **新增**编辑器前端（apply / editor / layout / selector / studio / studio.css / studio.js / app.png 等） |
| `public/ui-editor/images/` | **新增**（1.1.0）你上传用来替换 UI 的图片 |
| `public/ui-layout.json` | **新增**布局文件（普通开局也读它） |
| `public/index.html` | 在 `</body>` 前**加一行** `<script type="module" src="/ui-editor/apply.js">`；首次改动前备份为 `index.html.ui-editor.orig` |

游戏服务端、`server/`、`shared/` 等**完全不动**。

**卸载**：用备份还原 `index.html`，再删掉 `public/ui-editor/`（含 `images/`）和 `public/ui-layout.json` 即可。

## 5. 多版本兼容

- 编辑器只操作 DOM，换游戏版本不需要改逻辑；每个目录各自安装自己的 `public/ui-editor/`。
- 选中目录的服务端会**单独启动**，不会复用 :3000 上正在运行的别的版本/副本：
  - 3000 已被占用 → 自动用 3001、3002…；
  - 代理从 3123 开始顺延，互不干扰；
  - 正在运行的游戏不会被停止或修改。
- `server/index.js` 不存在时，还会尝试 `server/index.mjs`、`server/main.js`、`package.json` 的 `main`。
- 手机端 / 电脑端两套方案分开保存；切换设备方案会自动重新载入画面，未保存时会先询问。

## 6. 为什么需要代理

游戏的 CSP 是 `connect-src 'self'`，网页没法直接写游戏目录；改游戏服务端又会绑死版本。
所以工具起一个本机反向代理：

- 普通请求原样转发给所选目录的游戏服务端（含 WebSocket 隧道，联机对局照常）；
- 接管 `/ui-editor/layout`（读/写布局）、`/ui-editor/profiles`（存档）、`/ui-editor/meta`；
- **编辑器自己的静态文件由代理直接提供**，不依赖各版本游戏服务端的静态文件规则 / CSP / MIME；
- 浏览器始终同源，CSP 不用动。

## 7. 存档

工具目录下的 `profiles\`：

| 文件 | 说明 |
| --- | --- |
| `auto-<name>@<version>.json` | 当前版本的自动存档，每次保存同步更新 |
| `<名字>-<时间>.json` | 侧边栏「存」新建的命名存档（快照） |

侧边栏存档行：下拉选择 + 存 / 读 / 删。换版本不串档；整个 `profiles\` 可整体拷到新电脑 / 新版本。

## 8. 目录结构

```
Stronghold-UI-Editor\
  Start.bat                 双击入口（启动内置浏览器宿主）
  StrongholdUIEditor.exe    WebView2 宿主（窗口 / 选择页 / 编辑台）
  launch.ps1                备用启动器（--external 可走旧的系统浏览器模式）
  app.mjs                   主程序：校验 / 安装 / 服务端 / 代理 / 事件
  proxy.mjs                 反向代理 + 布局/存档/元信息接口 + 编辑器静态文件
  build-host.ps1            重新编译宿主（需要 .NET Framework csc）
  host\
    EditorHost.cs           宿主源码
    lib\                    WebView2 SDK（Core / WinForms / Loader）
    web\                    选择目录页（picker.html/css/js + app.ico/png）
  assets\                   要拷进游戏 public/ui-editor/ 的编辑器前端
  webview2\                 自带的固定版 WebView2 运行时（约 873 MB）

  README.md
```

## 9. 常见问题

**双击 Start.bat 没反应 / 闪退**
→ 先确认 `StrongholdUIEditor.exe` 和 `webview2\msedge.dll` 都在；日志在
`%LOCALAPPDATA%\StrongholdUIEditor\host.log`。

**提示「不是游戏目录」**
→ 要选包含 `public\index.html` 和 `server\` 的那一层，不是 `public` 里面，也不是上层。

**提示「没有找到 Node.js」**
→ 游戏包一般自带 `node\node.exe`；没有的话安装 Node.js 22+ 后重试。

**端口被占用**
→ 工具会自动顺延服务端端口（3001…）和代理端口（3124…）；也可以手动：
`"游戏目录\node\node.exe" app.mjs --embedded --game "D:\...\game" --port 3000 --proxy-port 3123`

**保存报错 / 侧边栏显示「接口未安装」**
→ 说明不是从工具的编辑代理打开的。用 `Start.bat` 进入，不要直接开 `http://127.0.0.1:3000`。

**手机端预览看起来是桌面布局**
→ 手机端舞台固定 767×329（21:9），触发游戏的窄屏布局；如果游戏版本自身在 767px 下仍是桌面排布，
那就是该版本的适配行为，不是编辑器的问题。

**想重新编译宿主**
→ 运行 `build-host.ps1`（使用 Windows 自带的 .NET Framework csc，不需要 Visual Studio）。

## 清晰度说明（2026-11-08）

- 元素用「缩放%」放大时，如果它原本带毛玻璃（`backdrop-filter`，例如标题页的开始框、缺人同盟卡片），Chromium 会把这一层按 1x 栅格化后再缩放，文字和边框就会发糊。现在布局 CSS 对 `scale != 1` 的元素自动追加 `backdrop-filter: none`（半透明底色保留），文字恢复清晰；代价是该元素放大后不再有背景毛玻璃。
- 预览舞台去掉了 `will-change: transform`，避免整个 iframe 被当成固定位图缩放。
- 修改后需在编辑器里点「重载」或重启工具，让新的 `layout.js` / `studio.css` 生效。
- 位图素材（`<img>` / 背景图）放大超过原始分辨率仍会糊，这是素材分辨率限制；需要更清晰就换更大的图，或改用宽高而不是缩放%。
